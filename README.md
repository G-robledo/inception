# Inception

An École 42 system-administration project using Docker Compose to run a WordPress site behind NGINX, with MariaDB for storage. Each service has its own Debian Bullseye-based Dockerfile.

## Services

| Service | Role |
| --- | --- |
| NGINX | HTTPS on port `443`, static files and PHP forwarding to WordPress |
| WordPress | WordPress installation through WP-CLI and PHP 7.4-FPM on port `9000` |
| MariaDB | Database and database-user initialization |

The services share a bridge network. WordPress files and MariaDB data use **host bind mounts**; the Compose file also declares named volumes, but the services currently mount host paths directly.

## Original machine and portability

This repository was configured for a specific Linux VM. It is **not a ready-to-run setup for an arbitrary machine**. The original layout uses `/home/greg/data` and the domain `grobledo.42.fr`.

Check these settings before starting:

| Setting | Location | Adaptation |
| --- | --- | --- |
| Host data directories | [`srcs/docker-compose.yml`](srcs/docker-compose.yml) | Review every `/home/greg/data/...` path and create the directories on the Docker host |
| Domain | [`NGINX configuration`](srcs/requirements/nginx/conf/default.conf) and `DOMAIN_NAME` in `srcs/.env` | Use the same hostname for NGINX and WordPress |
| Certificate subject | [`nginx_start.sh`](srcs/requirements/nginx/tools/nginx_start.sh) | Update the certificate subject if changing the hostname |
| Hostname resolution | The machine running the browser | Resolve the hostname to the VM or Docker host's IP address |
| Service configuration | `srcs/.env` and `secrets/.env` | Supply local database and WordPress settings |

For the original paths, create the directories **on the Linux Docker host**:

```sh
sudo mkdir -p /home/greg/data/mariadb /home/greg/data/wordpress /home/greg/data/nginx/ssl
```

The startup scripts adjust database and WordPress directory ownership inside the containers. Filesystem permissions and bind-mount support still need checking on another host.

NGINX generates a self-signed certificate when `grobledo.crt` or `grobledo.key` is absent from the SSL directory. If changing the hostname, replace the old local certificate as well as updating the configuration.

## Configuration

Clone the project:

```sh
git clone https://github.com/G-robledo/inception.git
cd inception
```

Review the two environment files before starting. For a local demonstration, their required variables can be arranged as follows; replace the example passwords with your own local values.

`secrets/.env`:

```dotenv
MYSQL_ROOT_PASSWORD=replace-with-local-root-password
MYSQL_PASSWORD=replace-with-local-database-password
WP_ADMIN_PASSWORD=replace-with-local-admin-password
WP_USER_PASSWORD=replace-with-local-user-password
```

`srcs/.env`:

```dotenv
MYSQL_DATABASE=wordpress
MYSQL_USER=wpuser
DOMAIN_NAME=grobledo.42.fr
WP_ADMIN_USER=siteowner
WP_ADMIN_EMAIL=admin@example.test
WP_USER=reader
WP_USER_EMAIL=reader@example.test
```

These files are loaded by the MariaDB and WordPress services. Keep real credentials out of commits. WordPress's active `wp-config.php` is generated by the startup script; the file under `requirements/wordpress/conf/` is not copied by the current Dockerfile.

## Validate and start

Prerequisites: Docker with a running daemon, the Docker Compose plugin, Make, an available port `443`, and the host-specific settings above.

First validate the Compose configuration:

```sh
docker compose -f srcs/docker-compose.yml config --quiet
```

This checks the configuration and environment-file availability. It does not prove that the services can start.

After adapting the machine configuration:

```sh
make
docker compose -f srcs/docker-compose.yml ps
docker compose -f srcs/docker-compose.yml logs -f
```

Open **https://grobledo.42.fr**, or your replacement hostname, after configuring name resolution. For a browser running on the Docker host, an `/etc/hosts` entry can point the domain to `127.0.0.1`; from another machine, use the Docker host's IP. Expect a browser warning for the local self-signed certificate.

## Stop and clean

| Command | Action |
| --- | --- |
| `make` / `make all` | Build images and start the services in the background |
| `make down` | Stop and remove this Compose project's containers and network |
| `make re` | Rebuild and start services, without clearing stored data |
| `make clean` | Bring down this Compose project and remove its local service images, named volumes and orphan containers |

Cleanup is scoped through `srcs/docker-compose.yml`; it does not list or remove every Docker resource on the host. **Host bind-mount directories and their contents are preserved**, including the WordPress files, database and certificates.

The Makefile uses `docker compose` by default. On a machine with the legacy standalone executable, use `make COMPOSE=docker-compose` and the same override for subsequent targets.

## Validation limits

The Compose model has been checked with example environment values, and the startup scripts pass shell syntax checks. A fresh installation and an end-to-end HTTPS check still need to be repeated on the intended VM. In particular, the MariaDB bootstrap starts a temporary `mysqld` without an explicit `--user=mysql`; first-start behavior must be checked before treating an empty data directory as supported.

If startup stalls, inspect the MariaDB logs first, then WordPress and NGINX. WordPress waits for a successful database connection, and NGINX waits for PHP-FPM on port `9000`.
